## Возможность → код → ограничения

Все операции находятся в [PgTaskQueue](../../src/main/java/io/github/alex59/pgtasklease/PgTaskQueue.java). [Полный пример](examples/Example.java) проверяет отправку, захват, heartbeat, отказ устаревшей аренде, повторы и восстановление; [пример отчёта](examples/ReportExample.java) показывает идемпотентный внешний результат.

| Публичная операция | Пример вызова | Результат и граница |
|---|---|---|
| Конструктор | new PgTaskQueue(connectionFactory) | Требует ненулевую фабрику R2DBC. Пулом управляет приложение. Миграция, планировщик и обработчик не устанавливаются. |
| submit(TaskRequest) | queue.submit(request) | Mono<Boolean>: true — вставка; false — UUID уже существует глобально среди всех очередей. Сохранённые поля не обновляются и не сравниваются. |
| claim(queue, owner, limit, leaseTime) | queue.claim("reports", "worker-a", 4, Duration.ofSeconds(30)) | Mono<List<TaskLease>>: неизменяемый ограниченный пакет; пустой, если задач нет. Атомарный SKIP LOCKED, предпочтение приоритета, без глобального FIFO и гарантии справедливости. |
| heartbeat(lease, leaseTime) | queue.heartbeat(lease, Duration.ofSeconds(30)) | Mono<Boolean>: продлевает текущую непросроченную аренду, не сокращая её. Исходный снимок не изменяется. |
| complete(lease) | queue.complete(lease) | Mono<Boolean>: true — переход в DONE; false — действующего владения нет, в том числе при повторном подтверждении. |
| fail(lease, retryDelay, error) | queue.fail(lease, Duration.ofSeconds(5), "report unavailable") | Mono<Boolean>: текущая аренда переходит в READY либо DEAD при исчерпании захватов. Текст ошибки хранится без изменений. |
| recoverExpired(queue, limit, retryDelay) | queue.recoverExpired("reports", 100, Duration.ZERO) | Mono<Integer>: количество восстановленных строк. Просроченные аренды переходят в READY/DEAD; несколько процессов восстановления допустимы. Запуск по расписанию организует хост. |
| find(id) | queue.find(taskId) | Mono<TaskSnapshot>: диагностический снимок; пустой Mono для неизвестного UUID. Владения не предоставляет. |

Вызовы выше используют уже созданные queue, request, lease и taskId: это фрагменты API, не самостоятельные программы. Импорты, соединения, порядок действий и проверки приведены в связанных примерах. [Практическое руководство](reports.ru.md) содержит сборку, запуск и ожидаемый CSV/вывод.

## Записи и состояния

- [TaskRequest](../../src/main/java/io/github/alex59/pgtasklease/TaskRequest.java): id, queue, payload, priority, maxAttempts, delay. Выберите и сохраните UUID до повторной отправки. Payload — непрозрачный ненулевой текст; сериализацию и ограничение размера задаёт приложение. Больший целый priority предпочтительнее; положительный maxAttempts считает захваты, включая потерянные из-за сбоя процесса.
- [TaskLease](../../src/main/java/io/github/alex59/pgtasklease/TaskLease.java): id, queue, payload, priority, attempt, maxAttempts, token, generation, owner, expiresAt. Token вместе с generation разрешает изменение; owner нужен для диагностики. expiresAt — первоначальный срок, а не результат последнего heartbeat. Не раскрывайте capability аренды.
- [TaskSnapshot](../../src/main/java/io/github/alex59/pgtasklease/TaskSnapshot.java): id, queue, state, attempts, maxAttempts, generation, availableAt, expiresAt, owner, lastError. Срок аренды и owner равны null вне LEASED; lastError также может быть null. Записи — неизменяемые снимки, не управляемые сущности.
- [TaskState](../../src/main/java/io/github/alex59/pgtasklease/TaskState.java): READY ждёт доступности и захвата; LEASED временно принадлежит работнику; DONE подтверждена; DEAD исчерпала попытки. Автоматического API перезапуска DEAD нет.

## Валидация и реактивное выполнение

Имя очереди непустое и не состоит только из пробелов, до 120 Java-символов; owner — до 200. Размер захвата/восстановления — 1..1000. Длительности задаются целыми миллисекундами, максимум 365 дней: leaseTime положителен, delay отправки и retryDelay допускают ноль. Текст ошибки ненулевой, до 2048 Java-символов; удаляйте секреты до сохранения. Проверка аргументов синхронна и предшествует SQL: обязательный null вызывает NullPointerException, неверный диапазон — IllegalArgumentException. Ошибки БД/соединения передаются через publisher.

Publisher холодный: до подписки выполнения нет; каждая подписка получает и закрывает одно auto-commit соединение. Повторная подписка повторяет операцию. Только submit с тем же сохранённым UUID имеет описанную дедупликацию отправки. Дожидайтесь результата; false не означает успешное подтверждение. Отмена/тайм-аут не доказывает, что БД не зафиксировала операцию.

## Схема, хранение и надёжность

Примените [pg-task-lease.sql](../../src/main/resources/pg-task-lease.sql) явно до использования. SQL обращается к public.pg_task_lease; настройки схемы, автоматического обновления и присоединения к доменной транзакции нет. Захват и защищённые обновления опираются на блокировки строк PostgreSQL, время БД и сохранность зафиксированных строк. Изменения по аренде повторно проверяют срок после получения блокировки.

Попытки не менее одного раза требуют работающих обработчиков и восстановления, достаточного бюджета попыток и долговечности БД. Побочный эффект может произойти до потерянного подтверждения; fencing очереди не отменяет и не защищает внешнюю систему. Делайте эффекты идемпотентными по UUID задачи либо используйте fencing во внешней системе. Если нужна атомарность отправки и доменной записи, транзакцию/outbox проектирует приложение.

API очистки нет. Удаляйте терминальные строки только по явной политике хранения, превышающей срок повторов отправителя и дедупликации. Удаление убирает историю UUID и сбрасывает последовательность generation строки при новой отправке того же UUID. Не удаляйте READY/LEASED при обычной очистке. Учитывайте чувствительность payload/ошибок, рост БД, индексы и vacuum.

Управляемый опрос, heartbeat, восстановление и обработчики через Spring-прокси описаны в [практическом случае стартера](reports.ru.md#сократить-служебный-код-через-spring-boot). Core не содержит регистрации через Spring/AOP.
